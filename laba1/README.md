## Описание бота

**хрючевальня** - Telegram-бот для сбора обратной связи о еде. Пользователь присылает фото своего блюда, а другие пользователи оценивают его по шкале от 🐷 до 🐷🐷🐷🐷🐷. Бот считает средние оценки, выносит вердикт, строит рейтинги блюд и мест, ведёт личную статистику, рассылает «Хрючево дня» и еженедельный отчёт администраторам.

Проект относится к варианту задания «Бот для сбора обратной связи»: бот собирает мнения пользователей, формирует сводные отчёты, отправляет уведомления администратору и ведёт статистику.

## Шкала 

| Оценка | Вердикт |
|---|---|
| 🐷 |  Обычная еда |
| 🐷🐷 |  Съедобно |
| 🐷🐷🐷 | Классика |
| 🐷🐷🐷🐷 | Уверенный продукт|
| 🐷🐷🐷🐷🐷 |  Хрючево |

Вердикт выносится по округлённой средней оценке, когда у блюда набирается не меньше 3 голосов.

## Структура проекта

- `bot.py` — основной файл бота: работа с базой данных, обработчики команд, диалог добавления блюда, оценки, статистика, задачи по расписанию;
- `requirements.txt` — зависимости проекта;
- `.env` — файл с секретами (не попадает в репозиторий);
- `.env.example` — шаблон конфигурации;
- `.gitignore` — список файлов, исключённых из системы контроля версий;
- `hryuchevo.db` — файл базы данных SQLite (создаётся автоматически при первом запуске);
- `README.md` — описание проекта и отчёт.

## Используемые технологии

- Python 3.10+
- [python-telegram-bot](https://python-telegram-bot.org/) v21 (асинхронный API, `ConversationHandler`, `JobQueue`)
- SQLite (стандартный модуль `sqlite3`)
- python-dotenv для загрузки конфигурации

## Проектирование базы данных

База данных содержит три таблицы:

- `users` — пользователи бота (Telegram ID, username, имя, дата регистрации);
- `posts` — блюда (автор, `file_id` фотографии в Telegram, название, место, цена, дата добавления);
- `ratings` — оценки (блюдо, пользователь, балл от 1 до 5, дата).

Места происхождения блюда: `canteen` (столовая), `dorm` (общага), `delivery` (доставка), `shop` (магазин), `homemade` (сам приготовил).

Средняя оценка в базе не хранится. Она вычисляется запросом (`AVG`, `COUNT`), поэтому данные не дублируются и всегда актуальны.

Составной первичный ключ `(post_id, user_id)` гарантирует на уровне базы, что один пользователь не может проголосовать за блюдо дважды.

## Реализация

### Регистрация пользователей

Пользователь регистрируется автоматически при любом обращении к боту. Для этого используется обработчик `TypeHandler` в группе `-1`: он срабатывает раньше всех остальных обработчиков и выполняет `INSERT … ON CONFLICT DO UPDATE`, обновляя username и имя при их изменении.

### Добавление блюда

Добавление реализовано как последовательный диалог через `ConversationHandler`:

1. отправка фото (командой `/new` или просто отправкой фото в чат);
2. ввод названия (от 1 до 100 символов);
3. выбор места кнопками;
4. ввод цены в рублях или пропуск этого шага.

После завершения диалога блюдо сохраняется в базе и становится доступным для оценки. Диалог можно прервать командой `/cancel`.

### Оценка блюд

По команде `/rate` бот присылает случайное чужое блюдо, которое пользователь ещё не оценивал, с кнопками 🐷1…🐷5. После нажатия:

- оценка сохраняется в базе;
- подпись под фото обновляется: показываются оценка пользователя, средняя оценка и вердикт;
- появляется кнопка «Следующее хрючево»;
- автор блюда получает уведомление о новой оценке, а при достижении 3 голосов дополнительно сообщение о вынесенном вердикте.

Оценить своё блюдо или проголосовать повторно нельзя: бот отвечает всплывающим предупреждением.

### Статистика и отчёты

| Команда | Описание |
|---|---|
| `/start`, `/help` | Справка по командам |
| `/new` | Добавить хрючево |
| `/rate` | Оценить случайное чужое блюдо |
| `/top` | Топ-10 самого хрючевного |
| `/antitop` | Топ-10 самой приличной еды |
| `/places` | Средняя хрючевальность по местам |
| `/my` | Последние 10 своих блюд с рейтингом |
| `/stats` | Личная статистика и звание |
| `/report` | Сводный отчёт за неделю (только для администраторов) |
| `/cancel` | Отменить добавление блюда |

В топы попадают только блюда, у которых не меньше 3 голосов.

Звание пользователя зависит от активности, то есть от суммы выложенных блюд и поставленных оценок:

| Действий | Звание |
|---|---|
| 0–4 |  Crook |
| 5–19 |  Босс |
| 20–49 |  Кабан |
| 50+ |  Повелитель  |

Отчёт администратора содержит данные за последние 7 дней: количество новых блюд и голосов, число активных пользователей, самого активного пользователя, хрючево недели, самое приличное блюдо, а также самое хрючевное и самое приличное место.

### Задачи по расписанию

С помощью `JobQueue` настроены две автоматические рассылки (часовой пояс задаётся в `.env`):

- **ежедневно в 20:00** всем пользователям приходит «Хрючево дня», блюдо с максимальной средней оценкой за последние сутки;
- **по понедельникам в 10:00** администраторам приходит еженедельный отчёт.

### Обработка ошибок

- проверка пользовательского ввода: длина названия, цена (целое число от 0 до 100 000), выбор места только кнопками;
- защита от повторного голосования и оценки собственного блюда;
- если пользователь заблокировал бота, это не прерывает рассылки и уведомления (исключение `Forbidden` перехватывается);
- глобальный обработчик ошибок записывает исключение в лог и отправляет пользователю понятное сообщение;
- при отсутствии токена бот завершает работу с подсказкой, что нужно заполнить `.env`;
- параметр сортировки, подставляемый в SQL-запрос, проверяется по белому списку, все остальные значения передаются как параметры запроса.
